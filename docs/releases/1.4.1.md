Quest Targets 1.4.1 improves native settings, keybindings and UI safety.

- Both targeting actions now appear under Options → Keybindings → Quest Targets, with primary and secondary binding slots.
- Assigning an occupied keyboard key or controller button in Quest Targets' own Hotkeys section now asks for confirmation before replacing the previous action.
- Changes made in WoW's native keybinding menu, including clearing focused-quest bindings, remain effective across refreshes and reloads.
- Quest Targets is registered in the native AddOn options at login. Opening settings through the minimap button first is no longer necessary.
- Native settings refresh through Blizzard's inbound entry point. Appearance-specific controls are disabled instead of hidden through callbacks in the shared settings search.
- Opening a quest in the native quest log is prevented during combat; right-clicking outside combat still opens the selected quest.
- QuestieDB map tables are read with a non-executing numeric parser. Map overrides and zero sentinels are preserved.
- Client interface pins cover Classic Era, Burning Crusade Classic, Mists of Pandaria Classic, Forever and Retail, including Retail interface 120105.

Packages: Classic, TBC, Mists and Forever include the corresponding official QuestieDB 1.0.9 package. Retail and the minimal ZIP contain Quest Targets only. SHA256SUMS.txt covers all six ZIPs.

Close WoW before updating and replace the existing QuestTargets folder. When using a combined package, replace the QuestieDB folder as well. Keep the full Questie addon enabled if you use its tracker.

Validation: 188 automated tests passed without skips, including all five flavor configurations, native keybinding synchronization, conflict confirmation, startup settings registration, combat guards, actual QuestieDB map data and package verification. These are automated Lua and packaging checks; live-client verification remains necessary. This release does not claim to eliminate every possible taint chain.
